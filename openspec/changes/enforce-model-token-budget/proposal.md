# Proposal

## Why

每日预算目前仅保存配置；任务步骤只能事后统计，不能防止并发调用同时耗尽预算。需要持久预留、单次发起许可与未知用量处理，并覆盖任务和模型诊断。

## What Changes

- 按可信租户/环境和北京时间调用准入日记录预留及实际结算。
- 使用经确认的单次输入加输出上限预留，不把估计字符数、max_tokens 或缓存命中当作可用额度。
- 引入原子预留、单次发起、未发起撤销、实际/未知结算与超出上限的故障阻断。
- 后续将任务模型、压缩调用与能力诊断接入同一账本，提供治理配置和占用展示；入口未全部接通前不开放启用。

## Capabilities

### New Capabilities

- `model-token-budget`: 统一模型调用预算执行与计量恢复。

### Modified Capabilities

无；现有每日任务统计保留按完成日统计，不伪造历史预留。

## Impact

工作台/治理 → 控制面预算服务 → MySQL；受信任务执行器和模型诊断 → 单次预算准入 → 现有模型 SDK。模型团队继续负责推理服务及其接口契约，不新增模型网关或推理设施。不改变任务终态、文件留存或物理回收权限。

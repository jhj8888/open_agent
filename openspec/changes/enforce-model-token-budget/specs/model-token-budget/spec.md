# Spec Delta

## ADDED Requirements

### Requirement: 可信且不可变的模型总量上限

系统 SHALL 仅接受运维核实的输入加输出总量契约，并在创建模型配置版本时固定其上限、来源、证据摘要及有效期，租户请求不能自报上限。

#### Scenario: 缺失、修改和失效

- **WHEN** 严格准入使用没有快照的旧版本，或契约被撤销、修改、尚未生效，或不足以覆盖请求最长时间
- **THEN** 拒绝严格调用，不以估算或输出上限回退，正常非限额模式不因此自动启用预算

#### Scenario: 模型身份和版本绑定

- **WHEN** endpoint、模型名称、适配器、思考模式或运维契约发生变化
- **THEN** 旧快照不会被改写，新配置版本重新捕获匹配契约，列表和审计只返回脱敏的契约信息

### Requirement: 原子预算预留

系统 SHALL 在可信调用范围内，使用输入加输出总量的可靠上限，在数据库原子预留每日预算。

#### Scenario: 并发预留与跨实例

- **WHEN** 多个 API/worker 同时请求相同环境预算
- **THEN** 已结算实际量与未结算预留之和不得因并发准入超过配置上限，不依赖进程内锁

#### Scenario: 稳定请求与配置降低

- **WHEN** 同一调用 ID 重试、以不同内容重用，或管理员降低预算
- **THEN** 同内容不重复占额，不同内容拒绝；降低预算不删除在途占额，阻止继续超额预留

### Requirement: 单次发起许可

系统 SHALL 将预留与外部调用发起分开，并仅发放一次发起许可。

#### Scenario: 发起回复丢失或重复

- **WHEN** 发起事务已提交但回复丢失或请求重试
- **THEN** 重试不发放第二次许可，保留预算占额，不自动重放模型请求

#### Scenario: 取消和跨日

- **WHEN** prepared 调用取消或跨过北京时间午夜
- **THEN** 未发起的预留可撤销；原日 prepared 不能在新日发起，新日必须重新准入

### Requirement: 可信结算与未知占额

系统 SHALL 保留实际输入输出用量，未知用量继续占用预留，不通过取消、任务删除或超时自动回收。

#### Scenario: 完成、重复和迟到结算

- **WHEN** 已发起调用返回 usage 或 unknown 后补回同次 usage
- **THEN** 原子将预留替换为实际输入输出，按原准入日记账；相同结算幂等，不同结算拒绝

#### Scenario: 提供方违反上限

- **WHEN** 实际输入加输出超过为该请求确认的上限
- **THEN** 保存完整实际用量和违约状态，阻断该环境后续预留和未发起调用，不能通过事务回滚抹去消耗

### Requirement: 完整执行接入

系统 SHALL 在开放预算开关前，将任务、压缩模型调用与模型诊断接入同一预算契约。

#### Scenario: 未完成接入

- **WHEN** 任一调用入口、可靠上限验证或存量切换尚未完成
- **THEN** 不宣称自动限额已启用，保持 tokenBudgetEnforced=false，拒绝开放能绕过预算的启用路径

# Design

## Context

阶段前端位于 console/frontend/preview，所有数据为示例。实际 platform 租户/Skill/model/Agent 接口和真实任务执行已存在。需要新增 console/frontend/workbench，保留既有预览，不让两种运行模式混淆。

## Decisions

1. 复用已认可的绿色/白色 CSS 与组件布局，用实际 API 数据和空状态替换示例数据。不得保留虚构成功率、资源用量或由浏览器生成的模型回复。
2. 认证使用维护中的官方 OIDC 客户端库和授权码 PKCE S256。客户端 ID 是公开配置；服务凭据及模型凭据不进入构建制品。模型密钥仅在配置提交时传给既有加密后端，不在页面回显或保存。令牌保存在内存，登录状态由标准会话流程恢复。
3. 租户/环境变化取消旧请求与订阅，清空相应缓存；服务端继续作为授权依据。生产发布依赖成功测试与固定版本，UI 不绕过现有门禁。
4. 聊天以部署 ID 调用既有异步 API；每次发送保留独立幂等键，重连只恢复事件。终态与错误由服务端决定，取消使用同一 API；消息使用 react-markdown 安全渲染，禁用原始 HTML、自动图片请求，保留默认 URL 校验。
5. 展示机入口使用专属 HTTPS 服务，仅代理明确的用户 API 和身份路径。私有内部路由禁止公网访问；不替换现有 80 端口应用。企业离线部署使用内部网关及内部 CA；公网证书自动化仅服务本次获授权展示机。
6. 统计来自实际数据，暂缺完整统计接口时明确标记范围或显示不可用，不使用占位数值伪装监控。权限错误、网络错误和空列表分别展示。

## Risks / Trade-offs

公网展示入口必须实际验证 TLS、OIDC issuer/回调和跨站请求边界。已有 Casdoor 私有 issuer 配置需要受控迁移，保留密钥与用户数据。旧预览始终可访问以供视觉对照。

## Migration Plan

先验证入口与身份，随后逐页接入实际数据和聊天，再做浏览器验收。独立工作台版本按摘要发布，切换静态目录可以回滚，不修改任务/审计历史。

# Proposal

## Why

企业共享同一平台，需要把人员、Agent、Skill、任务、日志和凭据的访问统一到可信租户边界。现有空间成员检查可以复用，但不能据此推断所有运行时资源已隔离。

## What Changes

- 定义企业租户与现有 space_id 的一对一映射和平台管理员、租户管理员、开发者、运维、只读角色。
- 加入租户创建/停用、成员角色、测试与生产权限、服务凭据和配额管理及审计。
- 所有资源查询和内部调用携带经鉴权确认的租户、环境、主体上下文。

## Capabilities

### New Capabilities

- `tenant-access`: 租户、环境和权限管理。

### Modified Capabilities

无。当前尚无已验收主规格；这是对现有代码的增量产品契约，不代表从零重写。

## Impact

控制台空间管理 UI → Java 认证与 SpaceAuthAspect → 各业务服务/核心服务。影响数据库查询、对象存储访问、任务与模型配置；复用 Casdoor，不新增身份系统。

边界：不涉及模型网关、模型调度、推理部署或模型运维；复用已有模型 HTTP 接口。

# Spec Delta

## Purpose

企业共享同一平台，需要把人员、Agent、Skill、任务、日志和凭据的访问统一到可信租户边界。现有空间成员检查可以复用，但不能据此推断所有运行时资源已隔离。 本能力用于定义企业内网 Agent 平台的可验证行为边界，使测试、部署、失败处理和权限控制具有一致的验收依据。

## ADDED Requirements

### Requirement: 首次登录登记

系统 SHALL 使用已验证 OIDC 身份登记本地账号，默认不分配租户、角色或生产执行权限。

#### Scenario: 新员工首次访问

- **WHEN** 已认证但尚未登记的用户进入工作台
- **THEN** 幂等登记其 JWT subject 并显示账号标识，供管理员显式添加成员

#### Scenario: 禁用及身份冲突

- **WHEN** 登记请求对应已禁用、已删除账号或仅数据库排序规则视为相同的其他 subject
- **THEN** 拒绝登记，不重新激活账号、不覆盖已有资料、不授予任何权限

#### Scenario: 伪造登记身份

- **WHEN** 调用方通过请求头或请求体指定其他用户或角色
- **THEN** 仅采用已验证 JWT subject，未认证请求返回 401

### Requirement: 可信租户上下文

系统 SHALL 从有效身份及成员关系解析租户、环境和角色，并拒绝客户端伪造的资源归属。

#### Scenario: 合法成员访问

- **WHEN** 成员访问其被授权租户的测试资源
- **THEN** 返回该租户测试环境的数据

#### Scenario: 跨租户访问

- **WHEN** 租户 A 成员提交租户 B 的资源 ID 或 tenant_id
- **THEN** 拒绝访问且不暴露 B 的资源是否存在

### Requirement: 成员与角色管理

系统 SHALL 允许获授权管理员管理租户和成员角色，并阻止普通成员提升自身权限。

#### Scenario: 管理员分配角色

- **WHEN** 租户管理员为本租户成员分配开发者角色
- **THEN** 保存生效并记录操作者与变更

#### Scenario: 禁止自行提权

- **WHEN** 开发者调用角色修改接口将自己改为管理员
- **THEN** 返回授权错误且角色不变

### Requirement: 环境权限隔离

系统 SHALL 分别授权测试与生产资源、发布操作及服务凭据。

#### Scenario: 测试权限受限

- **WHEN** 只有测试权限的开发者访问生产日志或执行生产部署
- **THEN** 拒绝请求且不返回生产配置

#### Scenario: 受权发布

- **WHEN** 有生产发布权限的运维发布已经验收的版本
- **THEN** 允许操作并记录发布审计

### Requirement: 租户生命周期

系统 SHALL 支持停用租户并禁止新任务；已接收任务按明确策略完成或由管理员取消。

#### Scenario: 停用后提交

- **WHEN** 停用租户尝试提交新的任务
- **THEN** 拒绝提交且不创建沙盒

#### Scenario: 保留历史

- **WHEN** 租户被停用但任务仍在审计保留期内
- **THEN** 获授权管理员仍可查询历史和取消存量任务

### Requirement: 配额与审计

系统 SHALL 允许管理员配置租户的任务并发、队列、沙盒及调用预算上限，并审计权限、配额与凭据变更。

#### Scenario: 调整配额

- **WHEN** 管理员降低配额至低于当前占用
- **THEN** 保留现有任务并禁止继续超额接入，展示占用与新上限

#### Scenario: 审计脱敏

- **WHEN** 管理员轮换服务凭据
- **THEN** 审计可追溯操作者和版本但不包含凭据明文

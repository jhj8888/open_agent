# Design

## Context

SpaceAuthAspect 已进行成员/权限校验；SkillFileService 使用 uid/space_id。core/tenant 的应用密钥管理不能当作完整运行配额控制。需要梳理个人空间到企业租户的迁移映射。

动机见 proposal.md；代码现状与证据见 docs/platform/baseline-assessment.md，实施顺序见 docs/platform/roadmap.md。

## Goals / Non-Goals

**Goals:** 落实 specs/tenant-access/spec.md 的可观察契约，保留上游已有能力并记录跨服务影响。

**Non-Goals:** 不接管模型部署、网关、调度、推理和运维；不将未完成的改造标为生产能力。

## Decisions

1. Casdoor 负责身份认证，Java 控制面拥有租户、角色、环境授权与服务凭据元数据。默认角色矩阵：平台管理员管理租户；租户管理员管理成员/配额/凭据；开发者编辑与运行测试；运维发布/回滚生产并查看脱敏运行记录；只读查看获授权元数据。生产执行使用单独的部署授权。角色修改需审计。
2. 现有企业 space_id 映射稳定 tenant_id，个人空间映射独立个人租户；禁止直接根据请求头覆盖。内部请求使用有受众、过期时间和请求身份绑定的服务认证上下文，入口网关只是第一层校验。
3. 环境是资源主键/授权条件的一部分。查询、缓存键、对象存储前缀和日志索引必须含 tenant_id/environment；对象下载经平台鉴权或使用短时受限签名。凭据只展示不可逆摘要/掩码，密文保存使用企业密钥管理接口或集群 Secret 引用。
4. 暂停租户禁止新任务及普通成员进入该租户业务资源，但不禁用其企业身份或其他租户权限；管理员/运维保留历史查看和显式取消。暂停前已持久接收的排队和运行任务默认继续，仍受配额、截止时间、租约、版本撤销与显式取消约束。归档是终止业务访问的独立状态，不获得暂停态的运行许可；依配置保留审计与任务记录，不做立即级联物理删除。
5. 复用现有权限体系并补齐资源授权，避免另建 Keycloak 或把每个租户做成独立身份服务。配额的定义在本变更，运行时原子执行在 persist-agent-runs。

## Risks / Trade-offs

[历史查询漏带租户] → 分资源审计并使用双租户回归；[角色变更缓存滞后] → 失效事件+短 TTL，关键操作实时校验；[个人空间误映射] → 映射报告和回滚表。

## Migration Plan

先增加租户/环境字段和映射表，回填并验证数据计数；影子校验差异后强制授权。回滚只允许回到仍执行隔离校验的版本；禁止恢复越权路径。

## Implementation Notes

每日任务用量增量调用链：工作台配额页 → JWT 治理控制器 → TenantGovernanceService → oa_run_step。沿用配额元数据权限及只读一致性快照；不返回任务正文、不修改共享身份、模型、执行器、对象存储或计费行为。按 Asia/Shanghai 自然日、模型步骤结束时间汇总至采样时刻，不按任务创建时间或列表分页截断；失败、取消、已删除任务的实际用量仍计入。输入总量已经包含缓存，合计只相加输入和输出。缓存未知保留 null；所有尚未结束的模型步骤另列为未结算，不能推断仍在物理运行。已结束但未知 usage 另计，不作为零消耗。该视图是自动预算限额的计量基础，不能作为并发请求已预留预算的证据；模型诊断不在任务步骤表中，明确不包含在本视图，自动限额仍待统一执行入口、在途预留与未知结算策略。

暂停在途任务调用链：治理状态 API 与 RunLedger 提交/领取/心跳/许可/事件/完成共享租户行锁；新任务仍要求 active，已接收任务仅允许 active 或 suspended。受信监督器、运行配置、Skill 读取、模型/工具执行前检查和步骤/产物持久化继续复用原租约许可，不扩大外部 HTTP 或模型诊断权限。取消、过期、错误身份和撤销版本保持原拒绝语义；archived 和未知状态拒绝后续执行。变更仅触及账本状态判断和说明，不修改共享登录、Kafka、Redis、对象存储、模型接口或 Python SDK。

2026-11-06 管理闭环增量：租户管理页 → 既有 JWT 治理控制器 → TenantGovernanceService → MySQL。配额读取增加同一只读快照下的排队任务、未释放执行槽与沙盒数；配置写入及审计仍仅包含配置字段。资源占用不因降低限额而强制释放，准入继续由现有任务账本执行。代码核验发现 daily_token_budget 当前只保存配置、尚无执行拦截；API 显式返回 tokenBudgetEnforced=false，UI 标明未启用自动限额，此项仍属于待交付范围。

审计接口保持数组响应和原 beforeId 参数，增加精确 action 筛选、无精度损失的十进制 cursor，以及最后一行的 nextBeforeId。每页最多 100 条，内部多取一条确认是否还有下一页；每次请求重新检查租户/环境审计权限，不把游标当授权凭据。工作台支持上一页、下一页、刷新最新及只读变更前/后详情；内容以文本呈现。retain_until 是现有记录的最短保留截止时间，改变配额只影响新审计，不能视为已实现过期自动删除。

最后管理员检查与 TenantAccessRepository 的实际成员边界对齐：候选管理员必须是有效账号，且仍属于未删除空间（个人租户须为本人）。修复不改变共享身份层或旧空间权限入口；旧入口整体收敛仍由 1.2 跟踪。UI 按现有角色/租户状态禁用治理操作，平台管理员无业务成员权限时不自动获得审计/配额数据；无租户的初始平台管理员可以创建首个租户。

独立平台入口提供 POST /platform/profile，首次访问幂等登记已验证 JWT subject；请求不接受角色、租户或账号 ID。复用 user_info 的唯一索引处理并发，重复项不更新任何资料，随后逐字比较 subject，拒绝大小写/重音排序碰撞及禁用/删除账号。新资料不创建租户、成员、管理员或用户协议同意记录。工作台先登记再读取租户；无权限页面展示自身账号标识，管理员通过既有审计接口授予权限。该入口不加载到旧 Hub 应用。

首个增量使用 V1.49 新增 `oa_tenant` 等表，采用 `space-<id>` 与 `user-<SHA256(uid)>` 稳定映射。存量成员仅回填测试环境；生产管理员由平台管理员显式登记，平台管理员不自动获得租户业务数据权限。治理 API 的授权、条件更新与审计在同一数据库事务内。原 SpaceAuthAspect/资源服务入口的收敛继续由任务 1.2/3.1 跟踪，不把新 API 的授权当作旧入口已经全部覆盖的证据。

操作与回滚说明见 `docs/platform/tenant-migration.md`；测试边界和未验收项见 `docs/platform/implementation-progress.md`。

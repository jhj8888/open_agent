# Spec Delta

## Purpose

现有进程内 asyncio 任务和带 TTL 的 Redis 事件不能保证服务重启后仍可追踪和恢复。平台需要持久运行记录、明确状态机、租户并发准入以及可验证的失败恢复语义。 本能力用于定义企业内网 Agent 平台的可验证行为边界，使测试、部署、失败处理和权限控制具有一致的验收依据。

## ADDED Requirements

### Requirement: 调度环境隔离

系统 SHALL 在 SQL outbox 领取阶段限定 test 或 prod，并由调度器验证返回环境后投递到该环境明确配置的 Temporal namespace 与任务队列；缺少旧客户端环境字段时仅兼容 test，不得解释为全部环境。

#### Scenario: 两环境并发出队

- **WHEN** 测试和生产调度器同时领取待投递或过期领取的消息
- **THEN** 各自仅领取本环境的 start/cancel 消息，不锁占另一环境的消息，任务不会进入另一环境队列

#### Scenario: 返回消息与调度器环境不符

- **WHEN** 控制面返回了另一环境的消息或调度器收到不匹配的直接投递请求
- **THEN** 在读取任务状态、启动工作流、发送取消或确认消息之前拒绝该消息，不把外部响应中的环境当作路由配置

#### Scenario: 旧调度器兼容

- **WHEN** 旧调度器未发送 environment 字段
- **THEN** 只领取 test 消息，prod 消息留给显式配置的生产调度器；空字符串和非法环境明确拒绝

#### Scenario: 未配置执行环境的部署

- **WHEN** 调用部署的环境尚未显式开启任务准入
- **THEN** 部署元数据返回 admission_enabled=false，提交返回 executor_unavailable，且不创建任务或 outbox；默认仅允许 test，生产开启须与生产调度器及执行后端就绪配套

### Requirement: 集群执行资源绑定与终止证明

系统 SHALL 将 Kubernetes 执行资源绑定到同一任务租约，持久记录环境、集群、namespace UID、Pod 名及唯一 UID，且仅接受独立受信监督器的回收证明。

#### Scenario: 集群监督服务就绪门禁

- **WHEN** 配置的 Temporal namespace 不存在或未注册，或者调度身份不能领取本环境消息
- **THEN** 服务不宣布就绪、不启动常驻出队循环，且不创建新的执行 attempt 或 Pod

#### Scenario: 集群监督器重启或扩容

- **WHEN** 一个新的监督器副本开始观察现有任务
- **THEN** 不主动 fencing 仍有有效租约的运行任务，只回收终态、取消、截止或心跳过期记录；不重新领取既有任务的启动授权或创建第二个 Pod

#### Scenario: Pod 已停但沙盒创建尚未核验

- **WHEN** Pod 停止证据已持久化，重新读取的 journal 表明沙盒创建已授权且缺少独立物理核验
- **THEN** 保留配额并继续补偿扫描，不以 executor 已停止代替沙盒与在途创建的终止证明

#### Scenario: 单次启动与身份隔离

- **WHEN** 集群监督器领取任务并请求启动授权
- **THEN** 准入和资源绑定原子提交，启动授权仅成功一次；其他监督器、环境、worker 或租户不能启动、替换资源 UID 或提交回收证明

#### Scenario: 终止记录先于删除

- **WHEN** 监督器确认已绑定 Pod 的 executor 容器终止
- **THEN** 先持久保存不可替换的终止证据，再允许凭相同 Pod UID、终止记录和沙盒核验结果提交最终释放；重启后可查同一证据并幂等释放

#### Scenario: 集群状态未知

- **WHEN** 创建响应丢失、节点失联、Pod 返回 404 或仅收到删除成功响应
- **THEN** 不把这些结果当成进程已终止，不重放执行，不释放尚未获得完整独立证明的配额

### Requirement: 受限运行配置读取

系统 SHALL 仅允许具备有效内部服务身份和当前执行租约的 worker 读取该任务绑定的模型/Skill 配置，并禁止将模型密钥或输入正文放入调度参数及结果。

#### Scenario: 租约失效后读取

- **WHEN** 任务取消、租约过期、worker 身份不符或绑定版本被撤销
- **THEN** 拒绝继续返回运行配置与 Skill 内容，对象读取期间发生取消也不返回内容

#### Scenario: 模型当前版本轮换

- **WHEN** 模型连接的当前版本发生轮换但部署绑定版本仍有效
- **THEN** worker 读取部署固定版本，不能隐式切换到新版本

### Requirement: 持久接入与幂等

系统 SHALL 在确认接入前持久保存 run_id 与执行快照，并对相同租户、环境和部署下的重复提交去重。

#### Scenario: 重复请求

- **WHEN** 相同幂等键及请求内容被重复提交
- **THEN** 返回同一 run_id 且只接入一次

#### Scenario: 键内容冲突

- **WHEN** 相同幂等键带不同请求内容
- **THEN** 返回冲突且不启动第二任务

### Requirement: 状态与重启恢复

系统 SHALL 在控制面或 worker 重启后保留任务状态，并明确区分可恢复步骤与结果未知的失败。

#### Scenario: 重启查询

- **WHEN** 控制面重启后查询已有 run_id
- **THEN** 返回持久状态与历史，不因缓存过期而丢失

#### Scenario: 未知副作用

- **WHEN** worker 在非幂等工具请求后丢失结果
- **THEN** 记录结果未知，禁止自动重复执行该副作用

### Requirement: 租户并发和背压

系统 SHALL 原子执行租户环境配额与排队上限，并避免单租户持续独占执行能力。

#### Scenario: 并发竞争

- **WHEN** 多个 API 实例同时为同租户提交超出执行上限的任务
- **THEN** 实际执行数不超过限额，余量按队列策略等待

#### Scenario: 队列满

- **WHEN** 租户达到排队上限
- **THEN** 返回可识别的限流错误与重试提示，不创建无界待执行任务

### Requirement: 取消与终态

系统 SHALL 支持幂等取消，停止后续模型/工具操作并回收资源，已确认终态不能被迟到事件覆盖。

#### Scenario: 取消排队任务

- **WHEN** 排队任务收到取消请求
- **THEN** 进入 cancelled 且不启动执行

#### Scenario: 终态竞态

- **WHEN** 成功与取消事件同时到达
- **THEN** 只有一个终态生效，状态、资源和审计保持一致

### Requirement: 事件与重连

系统 SHALL 按序保存事件并支持授权客户端断线重连，连接断开不代表任务取消。

#### Scenario: 断线重连

- **WHEN** 客户端带有效 Last-Event-ID 重新连接
- **THEN** 从下一事件继续，客户端可按序号去重

#### Scenario: 事件过期

- **WHEN** 重连位置已超出事件保留期
- **THEN** 返回明确过期错误并提供当前任务状态查询方式

### Requirement: 集群执行实体的安全生命周期

系统 SHALL 通过官方 Kubernetes SDK 创建固定配置的受信 executor Pod，使用租约绑定与 UID 前置条件操作，且在终止证据持久提交前保留平台 finalizer。

#### Scenario: 私有镜像仓库凭据绑定

- **WHEN** 操作者配置执行器的镜像拉取 Secret 名称列表
- **THEN** 将该列表显式纳入固定 Pod spec 与绑定摘要；只使用执行 namespace 内的 Secret 引用，不读取凭据正文；实际 Pod 被注入、删改或重排为不同配置时拒绝解除调度门禁

#### Scenario: 启动前的资源核验

- **WHEN** 新 Pod 已创建但安全配置尚未核验，或 UID 尚未确认写入账本
- **THEN** 保留 scheduling gate，不允许该 Pod 被调度；只有绑定成功后才能通过 UID/resourceVersion 前置条件解除门禁

#### Scenario: 创建回复丢失或监督进程重启

- **WHEN** 单次创建已发出但结果未知，或监督进程在记录 Pod UID 前重启
- **THEN** 只查询并核对同名 Pod 的完整绑定，不再次创建；未找到时保留配额

#### Scenario: 创建收到明确的存储前拒绝

- **WHEN** 本次唯一 Pod 创建调用收到完整的 Kubernetes v1 Status Failure，HTTP 401/403/422 与 Unauthorized/Forbidden/Invalid 对应，并携带有效审计请求 ID
- **THEN** 受信监督器保存与租约、Pod 名称、namespace UID 绑定的请求及响应摘要；控制面同事务固定失败或既有取消状态并 fencing，拒绝凭据不可替换。独立确认没有 Pod 和已授权沙盒创建后，凭该持久拒绝记录幂等释放配额

#### Scenario: 拒绝响应含糊或凭据写入失败

- **WHEN** 创建超时、返回 409/429/5xx、响应不符合拒绝协议、缺失审计 ID，或拒绝凭据未能持久保存
- **THEN** 不将它等同于明确拒绝，不重复创建或依据 404 自动释放；持久保存成功但回复丢失时可通过账本恢复同一拒绝记录

#### Scenario: Pod 名称被复用或配置被注入

- **WHEN** Pod UID、租约、镜像、容器或敏感安全配置与预期不符
- **THEN** 拒绝启动确认和删除，不操作替换资源，不释放配额

#### Scenario: 回收时证据提交失败

- **WHEN** executor 终止记录无法写入控制面
- **THEN** 保留 Pod 的平台 finalizer，后续从原 Pod 的终止状态继续核验，不丢失证据

#### Scenario: 尚未绑定节点时取消

- **WHEN** 任务已被 fencing，匹配的 Pod 未绑定节点且没有任何容器状态或提名节点，平台 scheduling gate 可以尚在或已移除
- **THEN** 使用 UID/resourceVersion 条件请求删除，再读取并确认 deletionTimestamp 与未绑定/未运行状态，持久登记独立的未启动证据后才移除 finalizer；旧版本激活及删除后的节点绑定请求被拒绝

#### Scenario: 未启动证据与已运行状态冲突

- **WHEN** Pod 已绑定节点、已出现容器状态或提名节点，或账本已有实际容器终止证据
- **THEN** 不接受未启动证明，仍走实际终止核验或保留资源配额

### Requirement: 执行配置读取容错

系统 SHALL 仅在没有开始模型或工具调用的只读运行配置获取阶段，对传输失败进行最多一次重试，并在重试前重新验证有效租约；日志只包含固定错误分类。

#### Scenario: 短暂传输故障

- **WHEN** runtime 读取遇到传输故障且续约确认任务仍获准
- **THEN** 最多重新读取一次相同租约的配置，不创建第二个任务或重放副作用

#### Scenario: 撤销或无效响应

- **WHEN** 配置读取被 HTTP 权限拒绝、返回格式错误，或者重试前续约失败
- **THEN** 停止读取，不继续模型或沙盒操作，不将原始错误内容写入日志

### Requirement: 独立执行监督与回收证明

系统 SHALL 在执行准入事务中记录受信 supervisor 与执行实体的绑定，启动授权只允许领取一次；只有绑定的独立回收身份可以在任务被 fencing 后提交实体停止证明并释放执行及沙盒配额。

#### Scenario: 普通 worker 声称清理完成

- **WHEN** executor 使用 worker 身份请求回收证明提交或其他 supervisor 的尝试
- **THEN** 请求被拒绝，配额与审计不发生变更

#### Scenario: 未知创建结果

- **WHEN** 启动或沙盒创建授权已领取，但回收器无法确认实体或在途操作已经结束
- **THEN** 保留配额并持续核验，不依据超时或空列表自动释放

#### Scenario: 核验与任务终态竞争

- **WHEN** 回收器核验停止的执行实体并提交对应证明
- **THEN** 保留数据库已有终态，证明、资源释放和审计在同一事务持久化

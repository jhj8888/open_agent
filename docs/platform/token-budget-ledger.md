# 模型预算账本

本增量实现预算执行所需的内部事务账本，尚未接入任务或模型诊断，不开放启用开关。配额 API 的 `tokenBudgetEnforced` 仍为 false；每日任务用量展示保持原有口径。

## 契约

`TokenBudgetLedger` 使用既有租户/环境行锁，预算变更与并发预留共享数据库边界，不依赖单实例锁。实际消耗和占额存于 V1.70 的 `oa_model_token_day`，逐调用事实存于 `oa_model_token_reservation`；所有变更在同一事务提交，失败同时回滚。计数使用 DECIMAL，不用浮点计算预算。

一次调用经历 `prepared → dispatched → settled | unknown | breached`。未发起的 prepared 可转 cancelled；dispatched/unknown 不能通过超时、任务取消或清理释放。unknown 后可由可信同次 usage 结算，迟到 unknown 不覆盖已知值。请求 ID 与摘要、上限绑定，相同准备重试返回原收据，不等于执行许可；dispatch 只成功一次，回复丢失后重试返回无许可，避免重复外部请求。

预算按北京时间准入日固定，生产使用共享数据库时钟，避免各 API 宿主时钟偏差。prepared 跨午夜后不可发起，应撤销并重新准入；已经发起的调用跨日结算修正原日。未知占额保留在原日，历史记录不会在零点删除。每日任务报表仍按调用完成日统计，未来预算 UI 必须区分这两种口径。

预留必须使用可信的输入加输出总量上限。单独的 `max_tokens` 仅为输出参数；字符估计不能用于严格限额。DeepSeek 官方 [模型元数据](https://api-docs.deepseek.com/api/list-models/) 定义了输入输出合计的 context_window，但字段可能缺失，且内网兼容接口仍需单独确认；这不是默认启用的依据。

actual input + output 超过声明上限时，账本保存完整有效实际值并标记 breached，拒绝该环境后续准备和未发起调用，跨日仍阻断。不能抛异常回滚已经发生的实际消费。未提供违约修复入口前，不能开放完整预算模式。缓存已经包含在输入中，不重复计量。

## 边界与后续接线

此类是内部持久化边界，不是 HTTP 授权入口。调用者须在相同事务的 authorize 回调重新验证可信租户/环境和执行身份，不能接收用户声明的模型上限。该回调不得执行模型或其他网络请求。未来调用链为任务/诊断 → prepare → 单次 dispatch → 官方 SDK → 结算；通用任务租约、文件归档和资源清理不使用预算可用量作为许可条件。

尚待交付：不可变模型上限与来源验证、所有实际请求入口与压缩调用接线、诊断逐步结算、存量启用策略、带审计的治理/违约修复、预算占用页面和真实模型并发/故障验收。不能用本次账本测试声称自动预算限额已生效。

## 迁移与验证

V1.70 仅新增两张表、约束和索引，保持现有数据。当前没有实际预算记录或启用入口，回退已验证的 V1.69 应用时保留新表即可；一旦执行链启用，不允许回退到忽略预算的版本。不得删除未知调用来恢复额度。

真实 MySQL 覆盖：两个服务实例的并发预留、重复发起、未知/迟到/冲突结算、午夜、预算降低与零限额、跨范围/权限撤销、上限违约、数据库触发器导致的事务失败、强杀数据库后的持久恢复。计数同时与逐条预留记录核对。数据库时钟和物理约束另行验证。

打包应用迁移测试使用独占的 V1.69 夹具库，实际新 JAR 通过 Flyway 迁移至 1.70，随后旧 JAR 启动查询原任务和配额，再恢复新 JAR。此测试证明本次未启用阶段的兼容性，不证明以后开启预算后还能安全回退。Flyway 对 future migration 的默认验证行为已核对[官方说明](https://documentation.red-gate.com/fd/flyway-ignore-migration-patterns-setting-277579002.html)；仍以本项目固定制品实测为准。

当前没有 Context7 工具；实现沿用仓库既有 Spring JDBC/事务与 JDK 接口，没有新增依赖。最终制品、部署和验证结果另存 JSON 证据。

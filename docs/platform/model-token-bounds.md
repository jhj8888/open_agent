# 模型总量上限契约

预算账本需要可靠的单次输入加输出总量上限。本增量提供运维契约配置、模型版本快照及严格准入时的校验方法；尚未把它接入实际模型调用，不开放预算开关。`tokenBudgetEnforced` 仍为 false。

## 信任来源与配置

平台运维从模型团队取得对实际 endpoint、模型名称、适配器和思考模式有效的总量约束，核实原始资料后配置 `MODEL_TOKEN_BOUND_CONTRACTS`。不支持租户通过 HTTP 声明这个数值，不提供猜测或默认上限。证据摘要用于复核配置来源，不等同于对提供方约束的密码学证明；若模型实际上违反约束，后续执行接线必须用预算账本的 breached 状态阻断，不能丢弃实际消费。

DeepSeek 官方 [模型元数据](https://api-docs.deepseek.com/api/list-models/) 区分 input+output 的 `context_window` 与仅输出的 `max_output_tokens`，并说明元数据可以缺失。只有核实实际配置返回的模型身份与总量契约后才能登记，不能把文档示例的数值套给另一模型或别名。内网 OpenAI 兼容接口没有这些字段时，由模型团队提供可复核的服务约束；不自动请求外网。

以下仅是 JSON 结构示例，数值和摘要均为合成数据，不能直接用于真实服务：

```json
[
  {
    "endpoint": "https://model.example.internal/v1",
    "modelName": "team-model",
    "adapter": "deepseek",
    "thinkingEnabled": true,
    "maxTotalTokens": 100000,
    "sourceRef": "model-team/contract-20261106",
    "evidenceSha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "verifiedAt": "2026-11-06T00:00:00Z",
    "validUntil": "2026-11-13T00:00:00Z"
  }
]
```

默认是空数组。每个模型身份只能有一条契约；字段缺失、多余字段、重复 JSON 属性、重复身份、字符串/小数上限、零/负上限和不合法有效期都拒绝启动。上限为 1 至 1,000,000,000 的整数；时间为毫秒精度 ISO-8601，核实时间早于失效时间。来源引用使用短标识，不包含密钥、正文或敏感查询参数。现有目的地址白名单与 DNS/TLS 校验继续独立生效。

Helm 的独立环境 `existingSecret` 可增加可选键 `MODEL_TOKEN_BOUND_CONTRACTS`，只注入 API，web 和沙盒不读取它。直接部署可通过受保护的服务环境配置同名变量。契约在进程启动时读取；变更、撤销必须更新所有 API 副本并完成重启，不能把 Secret 写入成功当作所有副本已切换。严格预算启用前仍需完成多副本契约版本一致性门禁。

## 不可变版本与失效

`ModelConnectionService.save` 在原有租户行锁和授权事务内捕获精确匹配的契约，与模型版本、凭据及创建审计原子提交。V1.71 新增从属表 `oa_model_token_bound`，不回填旧版本。契约快照记录总量、来源、证据/契约 SHA256 和 UTC 毫秒有效期；不按宿主时区存储时间。

重新保存连接创建新版本，旧快照不更新。改变 endpoint、模型名称、适配器或思考模式必须精确匹配另一契约；没有匹配时该新版本仍可用于现有非限额模式，但没有严格调用资格。匹配契约尚未生效或有效期不足以覆盖整个 `totalTimeoutSeconds` 时，保存被拒绝。模型列表增加只读总量、来源、契约摘要和失效时间；模型创建审计记录契约摘要与总量，不包含凭据。

内部 `tokenBoundForAuthorizedVersion` 校验连接启用、版本未撤销、当前契约与快照全部相同，并使用共享 MySQL 时钟检查剩余有效期严格大于调用总超时。它不提供对外授权：后续调用者必须在租户/环境锁内重新验证身份和精确任务版本，准备与发起都需检查。缺失快照、配置删除/修改、未来/过期契约或数据库快照不一致均拒绝严格调用。

本方法不改写当前版本指针，不解密凭据，不执行网络请求。旧版本即使被新版本替代，只要未撤销、对应运维契约仍有效，仍可由固定部署引用。

## 迁移及验收范围

V1.71 仅新增表、外键和约束。旧应用可以保留此表运行，但它创建的新模型版本不会有契约快照；预算执行启用后不得回退到忽略预算的应用。当前阶段预算开关关闭且没有真实批准契约，不影响演示站已有模型调用。

真实 MySQL 检查覆盖版本更新不回填、契约变化/删除、身份模式切换、跨范围与角色拒绝、版本撤销、禁用连接、快照篡改拒绝，以及插入失败时版本指针/凭据/撤销状态/审计一起回滚。合成契约仅证明平台行为，不能代替内网模型服务遵约验收。

当前工具集中无 Context7；沿用现有 Spring JDBC/JCE，使用 Jackson 官方 ObjectReader 的重复键和尾随内容检查，接口参考[官方源码](https://github.com/FasterXML/jackson-databind/blob/2.18/src/main/java/com/fasterxml/jackson/databind/ObjectReader.java)，没有新增依赖。实际调用、压缩请求、诊断、预算治理和真实并发故障验收继续保留未完成。

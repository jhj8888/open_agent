# 任务模型调用预算接线

2026-11-06：V1.72 新增任务逐调用归属和私有 worker 接口。实际 Java API、Python RuntimeExecutor、官方模型 SDK 与真实 MySQL 的联合测试通过；模型服务为测试进程内的合成 SSE 提供方。生产仍保持 `tokenBudgetEnforced=false`，本次不能作为企业环境预算已启用的证据。

## 调用链和边界

DeepAgents/压缩中间件的官方 LangChain 回调 → `ModelBudget` → `PermitTransport` → 私有 worker `model-calls` API → `RunLedger` → `TokenBudgetLedger`。`prepare` 和 `dispatch` 重新检查当前任务租约、可信 worker、部署固定的模型版本及运维契约；客户端不传可用额度或上限。V1.72 的 `oa_run_model_token_call` 与预算预留在同一事务绑定调用 ID、run/attempt/lease、请求摘要、模型版本和契约摘要。

一个逻辑回调只能发起一个物理请求。无上下文、重复物理请求或发起回复丢失均不发送模型请求。官方缓存命中没有 HTTP 请求时不预留。压缩模型调用继承回调，并拥有独立调用 ID、预留与结算。输入 Token 已包含缓存 Token，结算不重复相加。

只有完整成功响应的明确 input/output usage 可以结算；两字段必须存在，显式零合法。中断、失败或缺失 usage 保留未知占额。结算回复丢失可以以原 ID 和用量重试，但不重试模型。取消、释放租约或撤销模型后，原可信 worker 仍可提交同一历史 attempt 的迟到计量，不能再次取得发起许可。预算检查与普通 permit 分开，事件、产物、心跳及清理不因预算耗尽被封锁。

## 部署和后续启用

Java 当前不下发 `modelBudgetProtocol`；只有拥有的联合测试夹具在内存中注入 `v1`。任务请求或租户不能启用它。Linux worker 新源已作为不可变制品暂存并验证，实际服务切换状态以交付记录为准。生产总准入仍需同时完成 Java 模型诊断、真实提供方契约核实、多副本策略一致性、有审计的治理/启停和存量切换。原 OpenSpec 2.1/2.2 等完整验收项保持未完成。

V1.72 仅增加从属表，备份需包含调用归属和预算账本。旧应用兼容回退仅适用于预算未启用、契约/预留/归属表为空的当前阶段；启用后不得回退到可绕过预算的版本。单次新增表部署不等于完整离线镜像已更新。

展示 API 已更新至 V1.72，维护 43.46 秒且部署前保存私有备份。原任务 58 步、2 个文件 SHA256、缓存/周月/每日统计及五个服务健康复查通过；五个新增私有 worker 路由均被公网拒绝。worker 新源仅暂存并验证，活动服务源未切换，前端未改动且本轮没有重复浏览器验收。第一次拉取统计报告时文件名少写一个 `s`，远端检查已通过；改正下载路径后取得同次报告。详见 [交付记录](run-model-budget-delivery-20261106.json)。

# 任务历史检索

任务中心直接查询当前租户、环境中的保留任务，按创建时间、任务 ID 降序分页；不再依赖最近 100 个部署及每部署 50 条记录的组合。可按 Agent 名称字面子串、任务 ID 前缀搜索，筛选全部、进行中、已完成、失败与超时、已取消；每页可选 10 / 25 / 50 条，默认 25。当前页在一次请求结束 10 秒后更新，慢请求不会被固定间隔轮询不断中止。返回最新页获取新任务。

调用路径：`workbench/history.tsx` → JWT 管理接口 → `TaskHistoryService` → 成员与生产部署授权、任务/部署表、删除清单。打开历史任务独立读取部署元数据，再进入原有 `RunConsole` 的详情、步骤与文件接口；无须该部署仍出现在 Agent 列表中。首页最近任务也改为一次范围查询，首页卡片仍只统计最近 50 条，完整统计继续使用监控和周/月聚合。

## 接口

`GET /platform/tenants/{tenant}/environments/{test|prod}/runs`

| 参数 | 约束 |
|---|---|
| `limit` | 1–100，接口默认 50 |
| `before` | 上一页返回的 `next`；首页省略，最长 512 字符 |
| `state` | `all` / `active` / `succeeded` / `failed` / `cancelled`，默认 `all` |
| `search` | 最多 128 字符；剔除两端空白，不接受控制字符；`%`、`_`、`!` 为字面文本 |

返回标准 `ApiResult`，`data` 包含 `items`、`hasMore`、`next`。最后一页 `next=null`。每行包括任务 ID、部署 ID、Agent 名称、状态、时间、trace ID、错误码和持久 `usage`；缺失用量仍为 `null`，不返回任务输入、快照或身份。响应 `Cache-Control: no-store`。旧 `/api/v1/agent-deployments/{id}/runs` 数组接口保持兼容。

游标保存 UTC 毫秒时间与任务 ID，不依赖页末记录仍存在，并绑定当前用户、租户、环境、筛选、搜索及页大小。它只是分页位置，不是授权凭据，不需要额外签名密钥；每次查询在现有租户锁内重新授权。具备日志读取权限的成员查询整个范围；生产委派成员只看到仍获授权部署中自己创建的任务。无日志权限且无有效生产委派返回 403；已删除记录排除；下载仍执行原有独立授权。修改筛选或页大小必须从首页开始。

实时状态变化可能使记录进入或离开筛选集合，分页不承诺数据库快照。游标后新增的较新任务通过返回首页查看；不返回推测总数。采用现有窗口索引与参数化 JDBC 查询，无新增数据库迁移、外部服务、缓存或依赖。大量文本搜索的容量仍需生产压测。

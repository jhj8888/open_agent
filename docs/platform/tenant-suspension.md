# 暂停租户与在途任务

暂停表示停止接收新任务。暂停前已持久接收的排队和运行任务继续执行；管理员或运维可以在任务中心显式取消。暂停不注销企业身份，也不修改其他租户的权限。工作台在租户管理页显示这一策略。

先前账本在领取、心跳、执行许可、事件写入和最终成功处都要求租户 `active`，导致暂停本身可能使已接收任务失败，与既定设计不符。本次将新任务准入的 `active` 要求保留，并统一已有任务的 `active/suspended` 判定。

调用链：治理状态 API 与任务提交共享租户行锁 → outbox/Temporal → 监督器领取 → worker 心跳及 `RunLedger.withPermit` → 固定模型/Skill 读取、模型/工具调用、步骤与产物写入 → 终态 → 独立物理回收。只修改账本判断，复用既有 Spring 事务和 SDK，不修改共享身份、消息服务、模型部署或 Python 执行器。既有 SDK 接口保持不变，验证脚本沿用仓库现有 httpx、DemoSession 和受限内部查询。

仍然生效的限制：

- 排队和执行并发限额、截止时间、有效 worker 身份与不可恢复的过期租约。
- 部署停用、模型版本撤销、Skill 不可用会拒绝后续执行许可；暂停不覆盖这些撤销。
- 显式取消后不再允许新的工具、模型或事件操作，迟到成功按取消规则处理。
- 任务终结不释放配额，必须等待独立监督器核实 executor 和沙盒停止。
- 归档不是暂停，不获得继续执行许可。外部部署凭据及普通成员的暂停态业务访问权限不扩大，管理员/运维仍可查询与取消。

## 验证方法

真实 MySQL 用例覆盖：一个已运行任务和一个排队任务在暂停后继续并成功；新任务被拒绝；排队取消、运行取消、撤销模型、过期租约、截止、伪造 worker 以及归档仍拒绝；暂停与 8 个 HTTP 服务层提交并发共享同一数据库边界；未释放执行槽及沙盒继续占额。

`deploy/platform/control/verify_tenant_suspension.py` 使用独立演示租户、正常 JWT 与真实模型/隔离 Skill。脚本等待真实 execute 工具开始后暂停租户，并验证：首任务继续产生模型调用和文件；第二任务由队列进入运行后显式取消；第三任务在排队时取消；新的提交拒绝；两个已运行任务的 executor/沙盒被独立回收、配额归零，文件可下载且摘要一致。模型凭据仅通过私有 stdin 传入。持久标记防止重新执行已提交任务，finally 只恢复这个验收租户。

# 删除任务及产物

任务结束后，当前环境的租户管理员可以在聊天调试窗口点击“删除任务”，阅读确认提示后删除。运行中、取消中或执行资源尚未释放时拒绝删除。删除立即隐藏任务详情、步骤、事件和文件入口；产物由后台清理，可在回执中刷新清理状态。历史用量、运行账本、版本验证引用与审计保留，删除不是历史计量或备份擦除。

## API 与权限

- `DELETE /api/v1/runs/{runId}`：已验证用户 JWT，当前租户/环境的 active tenant_admin；返回 202 和 `run_id/deleted_at/purged_at/files_status`。服务凭据、开发者、操作员、只读角色均不能删除。
- `GET /api/v1/runs/{runId}/deletion`：同样重新校验管理员权限，`files_status` 为 pending 或 complete。
- 资源未回收：409 `run_delete_not_ready`。同权限重复删除幂等，不重复写审计。撤权后不能沿用旧回执访问。
- 删除后任务列表隐藏，状态/事件/SSE/步骤/文件返回 404；保留原提交幂等键，重提同键返回 409 `run_deleted`，不会重新执行模型或工具。

## 事务、清理和统计

调用链为工作台 → AgentRunController/AgentRunService → DeploymentAuthorization → MySQL 墓碑/审计/取消发布事务 → TaskOutputService 定时对账 → 既有官方 S3 SDK。锁顺序是租户/环境/run/产物/上传记录；删除前验证终态、所有 attempt 和沙盒已释放，以及每个已发布对象都有持久上传清理键。审核失败或事务失败，所有删除写入一起回滚。

V1.68 新增 `oa_run_deletion` 与产物 run 索引。文件清理只使用已有上传记录的精确键，任何仍被其他任务引用的键不删除。清理失败、存储不可用或共享引用未解除时保留 pending 及逻辑容量；成功后记录 purged_at，产物容量查询才排除该任务。未删除任务无自动到期删除。候选上传仍需超过 15 分钟，每轮最多 20 条，错误退避和每日迟到写入复查沿用原策略，不承诺固定完成时限。

实际已消耗 Token、任务历史计数、周/月统计不扣减；监控和统计页面已标明包含删除任务的历史计量。审计、账本和备份按既有保留策略独立保存，无恢复按钮。删除不触发模型重试、任务取消或执行配额释放，也不扩大沙盒权限。

若旧上传在第一次清理完成后才返回失败，失败登记会同时重新打开删除清理状态，恢复容量占用；后续对账成功后再标记完成。公开 API 补齐 DELETE 的 CORS 预检与实际请求，仍要求 Bearer 身份，不使用 cookie 作为删除授权。

## 验证与回退边界

新增 6 项真实 MySQL 删除用例通过，覆盖授权、未终结/未回收拒绝、幂等、所有读取入口拒绝、存储错误重试、其他任务文件保留、审计故障回滚、共享键保护、迟到上传重开清理状态，以及删除记录跨数据库 SIGKILL/重启持久化。测试/生产各自校验成员关系，不把测试管理员当成生产管理员。各轮 Java 检查分别为 29、24、19、2 项通过，存在重叠，不相加；CORS 预检与带 Origin 的 DELETE 一并验证。

最终 API 制品在真实 MySQL/SeaweedFS 完成 17 阶段演练，增加了真实管理员授权、删除幂等、文件存储强杀后 pending、恢复后精确键清除和保留文件摘要核对，见 [存储证据](task-deletion-storage-verification-20261106.json)。夹具仅有合成身份/数据，未开放宿主端口，容器、卷及凭据已清理；时间戳在夹具库中推进，不代表实际等待 15 分钟。

2026-11-06 已部署展示 API V1.68 和新工作台，维护前保存私有 SQL 备份，维护 41.568 秒。通过真实公网 HTTPS 创建并仅删除专用合成任务 `f410825d`：匿名拒绝、重复删除、状态/JSON 事件/SSE/步骤/产物拒绝、列表隐藏、原请求键拒绝重放及后台清理回执全部通过。原演示任务 58 步、2 文件下载摘要、20 页缓存明细、四个统计周期和 21 项公网用量复查通过，三个前端资产摘要正确。完整 API/前端摘要及检查记录见 [部署证据](task-deletion-verification-20261106.json)。

前端新增确认提示、异步清理回执和刷新入口；防止删除前发起的列表/状态响应重新插入已删除任务。类型检查与生产构建通过，浏览器交互仍需单独验收。

上线后不要直接回退到不识别删除墓碑的旧 API：它可能重新暴露已隐藏的任务正文。V1.68 数据表及审计必须保留；已有删除记录时只能回退到同样执行墓碑访问检查的版本，或先关闭公开 API 再执行受控恢复。恢复备份时须同时保留/合并备份之后的删除记录，防止旧备份复活已删除任务。当前未提供自动合并恢复流程，此项仍是完整恢复验收的缺口。

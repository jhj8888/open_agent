# 产品范围

确认日期：2026-11-03。来源：项目需求及用户后续范围澄清。

企业私有化部署且生产环境不访问外网。已有 Kubernetes、企业入口网关和若干 CPU 服务器；15 台 H20 八卡服务器由模型团队管理，不属于本平台的资源调度范围。

## 本项目负责

- 租户、成员角色、环境权限、服务凭据、配额和审计。
- 以 `SKILL.md + 脚本/资源包` 管理 Skill；草稿编辑、不可变发布、测试与生产推广、回滚。
- 多个 Agent 和同一 Agent 的多个任务并发运行；租户自行上传代码按不可信代码隔离。
- 持久任务状态、事件、取消、失败恢复、日志、用量和平台运行统计。
- 每个已发布 Agent 可通过 HTTP 接口调用，并提供聊天调试窗口。
- Agent 平台、任务 worker、沙盒与依赖服务的离线交付和应用运维。
- 访问已有模型 API：接口登记、鉴权引用、能力匹配、超时取消、错误处理及可获得的 usage。

## 模型团队负责

模型选择与权重、模型部署/升级、推理引擎、模型网关、模型路由与调度、GPU 资源管理、模型服务性能与运行维护。

本项目不实现 vLLM/SGLang 部署、模型负载均衡、GPU 调度、模型副本扩缩容或推理集群监控。已有入口网关继续承担企业入口职责。

## 接口协作契约

| 模型团队提供 | Agent 平台使用方式 |
|---|---|
| 内网 endpoint、协议、模型名称与版本 | 登记为模型接口配置，Agent 引用配置版本 |
| 鉴权方式、凭据或发放机制、企业 CA | 只在可信服务中解析，不传入浏览器或租户代码沙盒 |
| 文本、SSE、tool calling、usage 等能力说明 | 调试和发布前做契约验证，不凭普通聊天成功推定工具调用可用 |
| 超时/限流/错误语义和容量边界 | 平台进行调用侧超时与任务准入，不改造模型调度 |
| 测试/生产接口与故障联络方式 | 环境分别配置并留存接入验收结果 |

首个适配假设为现有代码支持的 OpenAI-compatible API；真实协议需由模型团队提供的接口验证。实际 URL、模型名、凭据、CA、配额和 SLA 尚未给出，放在环境配置和验收记录中，不写入源码占位为真实值。

## MVP 与后续边界

MVP 完成七个变更中的核心闭环；自主 Agent-to-Agent 委派、跨任务常驻沙盒、自动规划大规模子任务不属于本次明确需求。保留扩展点，不把“多 Agent 沙盒”误写为已要求自主多 Agent 协作框架。

源码中已有的知识库、RPA、云插件和模型管理页面不表示这些功能全部纳入首期交付。按核心链路逐项确认依赖，可选组件默认不启用公网连接。
